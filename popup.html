每次点赞的实际延迟在上面的区间里随机取，不是固定值 —— 固定间隔的机械节奏比延迟本身更容易被识别成自动化。留一点延迟是为了让 X 先把回复处理完，太短可能点赞失败。

互动追踪
「你回TA / TA回你」的计数全靠认得出哪个账号是你。左侧导航没有头像链接时自动识别会失败，这时手填一次即可。数据面板里会显示当前认到的账号。
数据面板里的「继续下滑扫描」用这两个参数。X 用虚拟列表，滚过去的节点会被卸载，所以插件是边走边记的。间隔太短 X 还没渲染完就滚走了会漏记；轮数决定一次能翻多深。扫完停在当前位置，不滚回顶部——再点一次就接着往下，不用从头重扫。中途可随时停止。

评论区参考
开启后把这条帖子下面别人已发的回复一起给模型当仿写样本（这里的「自动下滑」只为多加载几条评论，加载完会滚回原位，与数据面板的「继续下滑扫描」是两回事）。它们是已经发出去、被这条帖子接纳了的回复，等于告诉模型「在这条帖子下面什么样的话是搭的」——模型会照着它们的语气、句长、口语程度和切入角度写，避免生成跟帖子不搭的通用回复。
回复对象始终是原帖作者，不会去回答评论里的提问、不会 @ 评论者（提问式评论会被整条剔除，实测能把跑偏率从 33% 压到 0）。
参考越多仿得越准，但 token 线性增长。评论多时优先取高赞。「自动下滑」会临时移动你的滚动位置，加载完自动滚回；想让参考更充分就把它打开。
行为与界面
「进帖自动生成」会在你每打开一条帖子时静默消耗一次 API 额度，按需开启。
「关注追踪」记录你自己的关注/取关与回关情况，用来防撞限、算冷却、列未回关名单。它还需要在面板「关注」页同意一次数据说明才会真正开始读 —— 未同意前一个关注类响应都不读。只记录不代操作，不会替你关注或取关任何人。
「关闭思考模式」对 qwen3.x 系列效果极大：实测延迟从 7-50 秒降到 1-2 秒、token 省约 75%。不支持该参数的服务商（如 glm）会自动回退重试，不影响使用。
